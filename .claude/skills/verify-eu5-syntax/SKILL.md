# Verify EU5 Syntax

## Why this exists

The Mongol Resurgence codebase was generated by earlier AI tools that invented
syntax wholesale. Measured, not assumed: of the ten top-level fields used across
MR's three situation files, **nine do not exist in EU5**. The only real one is
`visible`. Fabricated syntax parses as silence — the game loads the file, ignores
the block, and the mechanic simply never fires. Nothing errors. So the only
defence is citation.

**Rule: a keyword may enter a mod file only with a `file:line` from vanilla or
Prussian Destiny that uses it in the same position.** Not "it looks like EU4",
not "other Paradox games do this", not "MR already uses it" — MR is not evidence.

## Reference paths

From the repo root (`Mongol-Resurgence-1/`), the read-only reference is one level up:

```
REF="../Reference EU5 vanilla and Prussian Destiny"
VANILLA="$REF/Europa Universalis V/game"
PD="$REF/The Prussian Destiny"
```

Never write anything under `$REF` — it is a symlink to the real game install and
the working Prussian Destiny mod.

## Procedure

### 1. Extract the keywords to check

For the file under review, pull out every distinct identifier used in a
structural position — top-level block fields, effects, triggers, scope changers.
Indentation depth matters: a name valid at one nesting level may not be valid at
another.

```bash
# top-level fields of every block in a file
grep -oE '^\t[a-z_]+ =' path/to/file.txt | sort -u
```

### 2. Search vanilla first, then PD

Vanilla is ~51k files and is the authority. PD is 35 files but is *known to
work* — it shipped and was tested — so it is the better model for how the
pieces fit together.

```bash
grep -rn --include='*.txt' '\bkeyword\b' "$VANILLA/in_game/common/" | head
grep -rn 'keyword' "$PD/in_game/"
```

Search the *sibling directory* of the file type you are writing. A field that
exists in `common/advances/` proves nothing about `common/situations/`.

### 3. Classify each keyword

| Result | Verdict |
|---|---|
| Found in vanilla, same file type, same nesting depth | **Valid** — cite the file:line |
| Found only in a different file type or depth | **Suspect** — the position is unproven, report it |
| Found only in PD | **Valid** — PD is tested; still cite it |
| Found only in MR's own files | **Fabricated** — MR is not evidence of itself |
| Zero hits anywhere | **Fabricated** — do not use |

### 4. Derive the closed field set

For a given file type, the union of fields across all vanilla examples *is* the
allowed set. Anything outside it is fabricated by definition. To compute it:

```bash
cat "$VANILLA/in_game/common/situations/"*.txt | grep -oE '^\t[a-z_]+ =' | sort | uniq -c | sort -rn
```

Frequency is signal. A field in 22 of 22 files is core; a field in 1 of 22 is a
special case that needs its context understood before copying.

### 5. Report, do not fix

Output a table: keyword, verdict, citation (or "none found"), and the line in the
MR file. Group as **kesin hata** / **şüpheli** / **netleştirilmesi gereken**.
Write nothing until the user approves.

## Known-good closed sets

Derived from the reference tree. Re-derive rather than trusting this table if the
game version has changed.

**`common/situations/` top-level fields** (vanilla, 22 files):
`can_start` `can_end` `visible` `on_start` `on_monthly` `on_ended`
`monthly_spawn_chance` `map_color` `secondary_map_color` `hint_tag` `tooltip`
`legend_key` `voters` `resolution` `custom_description` `content_trigger`
`is_data_map` `international_organization_type`

Note `on_ended` (21 files) vs `on_ending` (2 files, and what PD uses) — these are
not interchangeable guesses; establish which applies before using either.

## Traps specific to this project

- **`exists = c:TAG` is wrong.** Use `country_exists = c:TAG`.
- **`set_variable` needs `name` and `value`**, not `name` twice.
- **Presence is not correctness.** `owns` was globally replaced with `controls`
  and the change passed a text search — but ownership and military control are
  different things, and whether the swap is semantically right for this scenario
  was never established. Grep proves a keyword is real; only reading the
  surrounding vanilla usage proves it means what you want.
- **Do not pattern-match from EU4/CK3/HOI4/Vic3/Stellaris.** EU5 syntax diverges.
  If the only justification is "this is how another Paradox game does it", it is
  a fabrication.

## When the reference is silent

If a concept genuinely appears nowhere in vanilla or PD, check in this order:

1. The wiki PDFs in `docs/` (Situation modding, Event modding, Mod structure, …)
2. `https://eu5.paradoxwikis.com/Europa_Universalis_5_Wiki`

If still unresolved, **ask the user**. Do not guess and do not ship the keyword.
