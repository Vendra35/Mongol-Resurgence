# Mongol Resurgence — Audit Report

> **STATUS: HISTORICAL RECORD — all findings below are RESOLVED.** This is the
> audit of the original AI-generated codebase, kept as the record of *why* the mod
> was rebuilt and as a catalogue of EU5 failure classes. It does **not** describe
> the current code. Later rounds found and fixed further classes not listed here:
> character-vs-country effect scope (`add_mil`), wrong-place location names
> (`zhongdu` vs `dadu`), Pontic-vs-Kazakh steppe geography, wargoal coverage vs
> phase goals, dead tags (HLG), unreachable failure branches, and a shared
> failsafe flag. The living statement of the rules is `../CLAUDE.md`; the final
> design is `MOD-DESIGN-IDEA.md`; the method is `EU5-MODDING-GUIDE.md`.

**Date:** 2026-07-21
**Scope:** all 22 files under `in_game/` and `main_menu/`, plus `.metadata/`
**Method:** every field, hook, tag and named reference checked against the vanilla
tree (~51k files) and The Prussian Destiny (35 files, tested/working).
Counts below are literal grep hit counts in the reference tree.

---

## Summary

The situation, event, on_action and game_rule layers are each either written in
EU4 syntax or located in directories EU5 does not read. That is the mod's entire
functional surface. Rebuilding these layers from PD's working files is likely
faster and lower-risk than patching them in place.

| Category | Count |
|---|---|
| Definite errors | 11 classes |
| Suspect | 5 |
| Needs clarification | 4 |

### 6. Neither on_action hook exists

`on_yearly_pulse` and `on_country_formed` — 0 hits. PD uses the real hooks
`yearly_country_pulse` and `monthly_country_pulse`.

### 7. `has_game_rule` is a scalar, not a block

Vanilla and PD both use `has_game_rule = option_name`.
MR uses `has_game_rule = { rule = rule_mongol_railroad setting = historical }` (EU4/Vic3).

### 8. Game rules dangle, and the definition shape is wrong

`rule_mongol_railroad` is defined **only** in the dead `in_game/` directory.
`main_menu/` defines `MR_mongol_historical_mode` / `MR_mongol_fantasy_mode` instead,
so every trigger referencing `rule_mongol_railroad` resolves to nothing.

MR's shape is `name` / `description` / `default = no` / `flag`. PD's working shape is
`default = <option_name>` plus named option sub-blocks each carrying `flag`.

### 9. Situation files

Nine of ten top-level fields are fabricated. Union across vanilla's 22 situation files
vs. MR's three:

| | fields |

Intersection: `visible`. Additionally `icon =` is embedded in all three situation
files; it belongs in the paired `.gui`.

## Suspect

- **`owns` → `controls` still semantically unvalidated.** The swap was made and passes
  a text search, but ownership and military control differ. Each site needs a
  judgement call about what the scenario actually requires.
- **Duplicate `effect = {` blocks** — three within one `on_yearly_pulse` entry. No
  vanilla precedent for repeating the key at that level.
- **`MOG`** (1 hit) — the design doc lists MOG among the invented tags.
- **`DEL`** — 0 hits in `setup/countries`.
- **Name drift** — metadata says "Mongol Railroad"; the project, folder and docs say
  "Mongol Resurgence".
- **`on_ended` (21 vanilla files) vs `on_ending` (2, and what PD uses).**

---

## Needs clarification

1. **Region replacements.** Real candidates exist — `north_china_region`,
   `east_china_region`, `south_china_region`, `west_china_region`, `steppes_region`,
   `russian_region`, `west_siberia_region`, `east_siberia_region` — but which map to
   the design intent is a decision, not a lookup.
2. **Yuan tag.** `CHI` exists and has a `CHI_f` formable. Is Yuan `CHI`, or a
   separate `YUA`?
3. **Ilkhanate.** `HLG` exists; the International Organization half of the design
   doc's claim is unconfirmed.
4. **Game rules location.** `main_menu` only (PD's choice), or is an `in_game` copy
   intended?

- All five locations exist: `karakorum`, `zhongdu`, `sarai_al_jadid`, `samarkand`, `baghdad`
- `mongolia_region`, `persia_region`, `culture_group:mongolian_group`,
  `government_type:steppe_horde`
- No `exists = c:TAG` occurrences — that fix held
- All 7 `set_variable` blocks correctly carry `value`

## Recommended fix order

1. **Metadata, directories, BOM** — cheap, mechanical, unblocks the mod actually loading
2. **Event layer** — largest rewrite; rebuild from PD's event files
3. **Situations** — rebuild against the real closed field set
4. **on_action + game rules** — correct hook names, PD's rule shape, resolve the dangling reference
5. **Tags and regions** — resolve the clarifications above, then fix call sites
6. **Semantics** — the `controls` judgement, design-doc conformance (three phases,
   birth failsafe by ~1370, completion failsafe 5 years before each end date)
