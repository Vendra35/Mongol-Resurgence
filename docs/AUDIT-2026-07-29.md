## DEFINITE

### D1. The Great Partition can never start — its arming event has no recipient
`in_game/common/situations/MR_mongol_dominance.txt:1247-1250`: the
delayed `trigger_event_silently = { id = mr_dominance.140 years = 30 }`
sits directly in `on_ending`, whose root is the SITUATION, and
`mr_dominance.140` is a `country_event` — no recipient exists. All 75
other MR call sites and all 313 vanilla situation call sites sit inside
a country scope. `effects.log` marks the effect legal in any scope, so
the failure is SILENT. `mr_partition_ready` has exactly one setter
(inside event 140) and one reader (`mr_can_start_partition`), so the
entire Great Partition — situation, GUI, CB, wargoal, 10 events, 8
triggers, 99 loc keys — never opens.
**Fix shape:** set `mr_partition_ready` directly in `on_ending` (state,
not an event — MR's own guide rule), or wrap the delayed call in
`every_country = { limit = { OR = { tag = MGO tag = MGE } } ... }`.

### D2. `KAZ` has no registry entry — the Kazakh successor cannot be instantiated
`MR_great_partition.txt:516` and `MR_partition_events.txt:286` do
`change_location_owner = c:KAZ`, but KAZ has NO
`culture_definition`/`religion_definition` block anywhere in vanilla
`in_game/setup/countries/` (it is a formable-only tag, `KAZ_f`), and MR
ships no additive registry file. The file's own comment claims all six
successor tags are registered — true for CRI/NOG/BSH/CHG/OIR, false for
KAZ. Decoder class: `country_manager.cpp:206 — Unknown country`.
**Fix shape:** an additive `in_game/setup/countries/` identity block
(two fields — the 1066 project's `zz_1066_new_countries.txt` is the
proven shape), or swap KAZ for a registered tag.

### D3. `fontsize_medium` is an invented GUI identifier
`using = fontsize_medium` in all four situation panel `.gui` files
(mongol_dominance:78, mongol_imperial:77, mongol_resurgence:61,
mr_great_partition:73). Zero uses in the entire vanilla install; the
real family is `Font_Size_Medium` (154 uses), and vanilla's own
situation-panel `text_multi` blocks carry no `using =` at all. Same
class as the fixed `textbox_single`: `pdx_gui_factory.cpp:624`.

### D4. An AI-born MGO never gets its rank raised
`set_country_rank_effect` for MGO exists only on the HUMAN "Banner
Offered" path (`MR_dominance_events.txt:410`). The four AI paths
(`MR_mongol_resurgence.txt:690/763/793/819`) call
`form_country = formable_country:MGO_f`, whose `form_effect` is EMPTY
(vanilla `00_formable_countries.txt:3615`), unlike MGE_f's. In an
all-AI game MGO keeps the converted horde's original rank — map name
survives (all four horde rank branches render "Horde") but the ruler
style degrades: "Khān" only at kingdom rank; duchy = "Noyan", county =
"Beg". This is the user's own bug from Debug-and-Test-Results.md:431,
fixed in one of five places.

### D5. Two harness checks scan ZERO items while printing "24 items"
`tools/verify_mod.py:288` and `:400` compute a real occurrence count
and then pass `len(code)` (the FILE count) to `check()`. Both checks
are vacuous today: 0 `any_owned_location` occurrences (the 89-to-0
conversion), 0 live `is_subject_of` lines (both remaining are
comments). The exact failure the harness exists to prevent, with live
escapees. **Fix:** pass the real count, re-arm both `min_count`s,
prove on a known positive.

### D6. The Great Partition takes a human Khaghan's land with no is_ai gate
`MR_great_partition.txt:427-580`: the collapse branch transfers every
`mr_in_claimant_realm` location to the six successors unconditionally —
`grep -c is_ai` on the file is 0, and `mr_in_claimant_realm` matches a
human player's own provinces. Violates MR's own CLAUDE.md human-choice
rule verbatim ("failsafes ... never take a player's land"), which the
other three completion failsafes honor on both sides. Second smaller
instance: birth-failsafe tier 3 (`MR_mongol_resurgence.txt:817`)
conscripts "anyone at all" and cancels their overlord's subject with no
is_ai gate on either side.
**Fix shape:** is_ai-gate the transfers, or a refusable event for the
human Khaghan (the postpone-option pattern).
