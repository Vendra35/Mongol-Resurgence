# CLAUDE.md — Mongol Resurgence (EU5 Mod)

## Project
A "Mongol Resurgence" mod for EU5, built on the architecture of Prussian Destiny.

## Folder layout
This repo is `Mongol-Resurgence-1/`. The reference tree sits **one level above it**,
as a symlink:

```
eu5/
├── Mongol-Resurgence-1/                            ← write here only
└── Reference EU5 vanilla and Prussian Destiny/     ← READ ONLY (symlink → ~/Downloads/EU5/...)
    ├── Europa Universalis V/game/                  ← vanilla, ~51k files
    └── The Prussian Destiny/                       ← working, tested reference mod
```

Path from inside the repo: `../Reference EU5 vanilla and Prussian Destiny/`.

The symlink points at the real game install and the working PD mod — writing there
corrupts the actual files. **Never write to it.**

## Hard rules

### Verification
- **Citation rule:** no field, effect or trigger enters a file without a `file:line`
  from vanilla or PD that uses it *in the same position*. "It looks right" is not
  evidence.
- **Existing MR code is guilty until proven innocent.** It was generated by
  Cline/DeepSeek. Never cite an MR file as proof of how EU5 syntax works.
- Tags are always exactly 3 letters. Never propose or use a 4-letter tag.
- Situation fields are a **closed set** — whatever the union across vanilla's 22
  situation files is. Measured: 9 of MR's 10 top-level fields are fabricated; only
  `visible` is real. Re-derive the set each time rather than trusting a memorized list.
- Never use a location/region/culture name without confirming it in vanilla.
  Historical plausibility is not evidence (`zhongdu` not `beijing`,
  `sarai_al_jadid` not `sarai`).
- **Grep is not enough.** A keyword existing does not mean it means what you want.
  The `owns`→`controls` change passed a text search but was never validated
  semantically (ownership vs. military control).
- Do not port or pattern-match syntax from other Paradox games (Victoria 3, CK3,
  HOI4, Stellaris, EU4). EU5's syntax is its own.

### Before building anything new
- **Search vanilla first.** Three proposed situations (Tumu Crisis, Treaty of Ugra, the
  Altan Khan conversion) all turned out to exist already — `flavor_chi_mon`,
  `flavor_MOS`/`flavor_LIT`, `buddhism_events.13`. Duplicating vanilla content doesn't
  just waste effort, it conflicts with working game systems. Hook in read-only instead.
- **Search the mod too.** 17 designed modifiers sat unused in `MR_modifiers.txt` while
  duplicates were written alongside them.
- Some vanilla state is unhookable: `treaty_of_ugra` is removed the moment its event
  resolves, so nothing durable survives to read. Confirm a signal persists before
  depending on it.

### Silent-failure rules
These two cost you an entire mechanic with no error message, no log line, no symptom.
- **Verify the directory name in vanilla before creating a file.** A file in a
  folder EU5 doesn't read loads as nothing. Measured: three MR files were in
  `on_actions/` (real name: `on_action`), `in_game/common/game_rules/` and
  `in_game/common/static_modifiers/` (both only exist under `main_menu/common/`).
- **Every cross-reference must resolve.** Game rule names, scripted_trigger names,
  localisation keys, gfx keys, on_action hook names. `rule_mongol_railroad` was
  referenced by triggers but defined only inside a dead directory — the whole
  historical/fantasy branch silently did nothing.

### Known bugs
- `country_exists = c:TAG`, never `exists = c:TAG`.
- `set_variable` takes `name` + `value` — not `name` twice.
- `has_game_rule` is a **scalar**: `has_game_rule = option_name`. The block form
  `has_game_rule = { rule = X setting = Y }` is EU4/Vic3 and does not exist in EU5.
- Events are keyed by the block name (`flavor_mr.1 = {`), not by
  `country_event = { id = ... }`. Every event file needs a `namespace =` line.
  `picture`, `mean_time_to_happen`, `pre_trigger` and `scope` do not exist in EU5 —
  use `image` / `illustration_tags`.
- Keep GFX/GUI references out of situation files; put them in separate `.gui` files.
- The `MGO_f` formable **already exists in vanilla** — do not create a
  `00_formable_countries.txt` for it. PD has that file only because NGC genuinely
  doesn't exist in vanilla; MGO is a different case.

### File format
- **Encoding: UTF-8 with BOM.** Every vanilla and PD file starts with `efbbbf`.
  11 MR files are currently missing it — don't skip the BOM on new files.
- **The English-only rule covers comments too.** PD's own source contains Turkish
  comments, which ride along when patterns are copied — strip them. (Proper names
  in localisation, like `Möngke`, are fine.)
- Naming: `MR_` prefix on files and variables, namespace `mongol_resurgence`,
  paralleling PD's `PD_` / `the_prussian_destiny`.

## Workflow
- Never write to a file without my approval.
- Read `docs/MOD-DESIGN-IDEA.md` before starting any task — it holds the full design
  detail (tag table, failsafe system, situation timeline).
- Categorize findings: **definite errors / suspect / needs clarification**.
- For any tag, name or field you're unsure about, search the vanilla files. If still
  unsure, check `https://eu5.paradoxwikis.com/Europa_Universalis_5_Wiki` or the wiki
  PDFs under `docs/`. Do not guess.

## Skills
Under `.claude/skills/`, named with a category prefix — skill discovery does not
recurse into nested folders, so the structure is flat names rather than subfolders:

- **`verify-eu5-syntax`** — prove every keyword against vanilla/PD with a citation
- **`verify-tags`** — resolve tags, formables, locations, regions, cultures
- **`audit-mod`** — categorized audit report across all known error classes
